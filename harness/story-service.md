# 서비스 유저스토리

출처: `interview_harness_prd.md` (Interview Preparation Harness v1.0)

## 유저스토리

| # | 유저스토리 | PRD 근거 |
|---|---|---|
| 1 | 경력직 프로덕트 디자이너가 기업명·직무·JD를 입력해 핵심 역량과 요구 경험을 우선순위와 함께 분석받는다. | 시나리오 A, JD 분석 카드 |
| 2 | 경력직 프로덕트 디자이너가 JD 요구사항을 기존 프로젝트·역량 카드와 근거 기반으로 매칭해 확인한다. | 시나리오 A·B, 역량 매칭 카드, 부록 A-3 |
| 3 | 경력직 프로덕트 디자이너가 기존 경험 카드를 재사용하되 지원 직무에 맞게 답변 초점만 조정한다. | 시나리오 B |
| 4 | 경력직 프로덕트 디자이너가 예상 질문·답변 카드를 생성하고 검토한 뒤 확정한다. | 시나리오 A, 산출물 4, 지켜야 할 것 |
| 5 | 경력직 프로덕트 디자이너가 실제 면접 질문과 피드백을 입력해 중복을 확인하고 부족한 답변을 보완해 카드에 연결한다. | 시나리오 C |

## 이 서비스에서 어기면 안 되는 것

| # | 내용 | PRD 근거 |
|---|---|---|
| 1 | 존재하지 않는 성과·경험·A/B 테스트를 만들어내지 않고, 원본 경험과 수치를 사실 그대로 유지한다. | 5장 "지켜야 할 것" 1번, "안 할 것" 1번, 부록 B 정확성 |
| 2 | 생성 결과는 사용자 검토 후 확정하고, 출처 확인 없이 기존 내용을 덮어쓰지 않는다. | 5장 "지켜야 할 것" 5번, "안 할 것" 4번 |

## 범위 메모

- 기존 면접 인덱스(HTML) 반영은 PRD상 연동 방식이 미정이라 스토리에 포함하지 않았다.
- "변경 이력 조회" 행동은 PRD에 없어 스토리에 포함하지 않았다.
