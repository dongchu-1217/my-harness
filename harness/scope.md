# 범위 (R2)

## 매번 달라지는 것
- 새 JD: 기업명, 직무명, JD 원문
- 고정: 카드 구조, 기존 프로젝트·역량 카드

## 하네스가 돌리는 작업
- 면접 카드 생성 (PRD 시나리오 A): JD 분석 → 경험 매칭 → 예상 질문·답변 카드
- 확정된 카드를 구조화 데이터(JSON 등)로 내보내고, 면접 인덱스 HTML(`프로덕트 디자이너 면접 인덱스.html`)에 하네스가 직접 반영한다.
  - PRD상 연동 방식은 "HTML 구조 확인 후 결정"이므로 반영 방식은 `확인 필요`다. (R3~R4에서 정한다.)
  - 반영은 사용자 확정 이후에만 하고, 출처 확인 없이 기존 내용을 덮어쓰지 않는다. (PRD 지켜야 할 것·안 할 것)
- 범위 밖: 화면 디자인 흐름(story-work 7문장), 음성 분석, AI 자동 채점

## 사용자
- 경력직 프로덕트 디자이너 (면접 준비자)

## 완료 기준 (한 문장)
JD 1건 입력 → 필수 필드가 모두 채워진 JD 분석 카드·역량 매칭 카드·예상 질문·답변 카드가 생성되고, 근거 없는 수치·경험이 0건이며, 사용자가 확정한 뒤 인덱스 HTML에 반영된다.
