# 역할 (R6)

## 역할 표

| 역할 | 하는 일 | 편집할 수 있는 곳 |
|---|---|---|
| 오케스트레이터 (메인 Claude, `CLAUDE.md`) | 트리거를 받아 단계를 진행하고, 판정 결과를 `state.json`과 `04-check.json`에 기록하고, 사용자 승인을 받는다. | 실행 폴더의 `state.json`, `04-check.json`, `review.md`, `harness/data/experiences.json` (사용자가 입력한 경험을 그대로 저장) |
| `card-writer` (S1~S3) | JD 분석 카드, 역량 매칭 카드, 예상 질문·답변 카드를 만든다. | `harness/runs/{실행 폴더}/` 안의 `01~03` 파일만 |
| `index-writer` (S5) | 승인된 카드를 인덱스 HTML에 반영하고 백업과 변경 이력을 남긴다. | 인덱스 HTML 파일 1개, `harness/runs/{실행 폴더}/05-*` |
| `judge` (읽기전용 판정자) | G1~G5와 S4 점검을 실행하고 결과를 출력한다. 파일을 고치지 않는다. | 없음 (읽기 전용) |

## 규칙
- 판정 로직은 `harness/scripts/judge.py`(Python)가 센다. `judge`는 그 결과를 출력만 한다.
- `card-writer`는 자기 단계의 결과만 쓰고 다음 단계 파일을 건드리지 않는다.
- `index-writer`의 편집 범위는 위 두 곳이 예외로 허용된 전부다. HTML 파일은 옮기지 않는다.
- 경험 카드는 사용자가 입력한 그대로 저장하고, 오케스트레이터가 내용을 고치지 않는다.

## 자연어 트리거

| 사용자 말 | 동작 |
|---|---|
| "경험 추가할게" | 경험 카드를 저장하고 `data/experiences.json`에 기록 |
| "{기업명} 면접 카드 만들어줘" | 새 실행 폴더 생성, S1~S4 진행 후 `review.md` 제시 |
| "승인" | 승인 기록 후 S5 실행 |
| "반려", "다시" | S3로 복귀 |
| "이어서" | `state.json`의 마지막 통과 단계 다음부터 재개 |

## 확인 필요
- Python 설치 여부는 R8 검증에서 확인한다.
